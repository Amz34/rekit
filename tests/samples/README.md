# Test fixtures

Everything the suite needs is generated here, so a fresh clone can run
`tests/run_rekit_suite.sh` without downloading anything.

| Fixture | What it exercises |
| --- | --- |
| `tiny.c` -> `tiny` | Dynamic ELF (aarch64): headers, sections, symbols, strings, disassembly. |
| `tiny2.c` -> `tiny2` | Optimised build: different code shapes, inlined helpers. |
| `tiny_asm.s` -> `tiny_asm` | Hand-written asm with the raw syscall sequence: instruction-level checks. |
| `tiny_static` | Static, unstripped build: large binary path, no dynamic symbols. |
| `sample.js` | Noisy JS bundle for the `js` lane (URLs, tokens, obfuscated blobs). |
| `test.pcap` | Generated by `make_test_pcap.py` with the standard library only (`struct`, no scapy/dpkt): DNS query+response, HTTP GET, TLS ClientHello with SNI. |

## Regenerate

```bash
./build_samples.sh                 # compiles the C/asm fixtures + pcap
python3 make_test_pcap.py          # pcap only
```

`build_samples.sh` uses `cc` (override with `CC=`), so the same script works on aarch64
and x86_64 hosts.

## Not vendored

The PE and APK lanes are exercised through environment variables pointing at samples you
already have, so no third-party binaries ship in this repository:

```bash
REKIT_PE_SAMPLE=/path/to/app.exe    # yara / iocs / capa / floss checks
REKIT_APK_SAMPLE=/path/to/app.apk   # apk / firmware checks
```

Unset variables make those checks report `SKIP`, never a fabricated pass.
